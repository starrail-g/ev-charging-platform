# 项目整体认知与同学 B 开发计划

> 版本：v0.3（2026-09-04）
> 适用范围：阶段 I 最小闭环，兼顾阶段 II 扩展

## 1. 项目整体认知

### 1.1 目标与验收主线

本项目是一个基于 Ubuntu + Qt/C++ 的电动汽车充电桩应用管理平台，覆盖用户服务、运营管理、持久化数据和 Web 可视化。第一阶段的关键不是一次性完成所有扩展，而是从干净环境启动以下可追溯链路：

```text
用户端/管理端 Qt
        | Socket
        v
服务端业务层
        | 事务化数据库访问
        v
SQLite（用户、站点、桩、订单、管理员）
        |
        +--> 管理端统计/管理页面
        +--> ECharts 大屏数据
```

项目说明书中的机器学习预测属于可在基础功能稳定后增加的扩展，不得挤占阶段 I 的基本闭环。

### 1.2 子系统边界

| 子系统 | 负责内容 | 不负责内容 |
|---|---|---|
| `apps/user-client` | 手机号免密登录、个人资料/余额、附近站点、导航、预约—充电—计费—结算 UI | 服务端持久化、管理员功能 |
| `apps/admin-client` | 管理员登录后的营收、桩状态、桩/站点/用户管理 UI | 核心业务规则和直接操作 SQLite |
| `server` | Socket 接入、认证、业务校验、订单/桩状态转换、统计查询 | Qt 页面绘制 |
| `libs/protocol` | 请求/响应消息、错误码、序列化和消息边界 | 业务规则、数据库 SQL |
| `libs/database` | SQLite 连接、迁移/初始化、查询和事务封装 | UI 和 Socket 会话管理 |
| `database` | Schema、迁移、种子数据 | 运行时业务代码 |
| `dashboard` | ECharts 展示和数据导入/读取 | 交易写入和核心状态修改 |
| `ml` | 负荷预测、推荐、预警扩展 | 阶段 I 基本业务闭环 |

### 1.3 核心业务状态与一致性

- 充电桩至少区分：`idle`（闲置）、`reserved`（预约）、`charging`（在用）、`fault`（故障）；`offline` 作为设备不可用状态保留。远程重启只能作用于允许的异常状态，并返回可观察结果。
- 订单状态覆盖需求规定的 `pending_reservation`（待预约）、`reserved`（已预约）、`charging`（充电中）、`pending_settlement`（待结算）、`completed`（已完成）、`cancelled`（已取消）和 `exception`（异常）。
- 进入充电前必须检查用户是否存在未完成订单；同一用户不能重复开始充电；无空闲桩、余额不足、桩状态冲突必须返回明确错误。
- 开始充电、结束计费、余额扣减、桩状态更新属于同一业务事务或有明确补偿策略，不能留下半更新数据。
- 金额使用整数分或 SQLite 明确精度规则；时间统一使用可序列化格式，并在文档中固定时区约定。

### 1.4 阶段依赖顺序

```text
需求矩阵
  -> 数据库字段/状态冻结
  -> Socket 帧与错误码冻结
  -> 服务端最小请求-数据库-响应
  -> A/C 接入真实接口
  -> 集成测试与干净环境演示
```

腾讯地图 Key 只进入本地配置，用户端保留 Mock/离线开关。服务端和大屏均应支持固定种子数据，保证答辩不依赖外网。

## 2. 同学 B 的职责边界

同学 B 担任 PRL + PE2，拥有以下模块的实现和接口质量责任：

- `server/`：Socket 服务端、会话/并发模型、管理员认证、订单/桩业务服务、统计查询。
- `libs/protocol/`：消息类型、请求编号、序列化、错误码、心跳/断连约定。
- `libs/database/` 与 `database/`：连接管理、Schema、初始化/迁移、种子数据、事务封装。
- 设计文档：`docs/architecture/database.md`、`docs/architecture/protocol.md`、相关 API 说明。
- 测试：数据层单元/集成用例、协议联调样例、异常路径验证。

不承担 `apps/admin-client` 的页面排版、Qt 图表编排、Web 大屏视觉和发布材料统筹；但要向 A/C 提供稳定的接口样例和启动说明。

## 3. 开发计划

### 阶段 0：契约准备（9 月 1–2 日）

**目标**：让 A/C 可以并行开发，不再依赖口头约定。

**任务**

1. 从需求矩阵提取实体和用例：用户、管理员、站点、桩、订单、钱包流水/统计所需字段。
2. 提交数据库草案：主键/外键、唯一约束、状态枚举、金额精度、索引、初始化管理员 `admin/123456` 和演示数据。
3. 提交协议草案：长度前缀或等价消息边界、版本、请求 ID、操作名、JSON/二进制载荷选择、统一错误码、心跳和断连行为。
4. 画出“开始充电—结束计费—结算”和远程重启的状态转换及事务边界。

**交付物/完成标准**

- `schema.sql` 可在空 SQLite 文件执行；重复执行不会破坏数据或有明确迁移策略。
- `protocol.md` 给出至少登录、站点/桩查询、开始/结束充电、结算、管理员查询、冻结/解冻、远程重启的请求/响应样例。
- A/C 能据此写客户端假实现和字段映射；未决问题显式列在文档中。

### 阶段 1：最小服务端闭环（9 月 3–6 日）

**目标**：完成“请求 → 校验 → SQLite → 响应”，优先支持演示主链路。

**任务**

1. 建立可构建的服务端入口、监听端口和配置读取；每个连接独立处理，耗时数据库操作不得阻塞其他连接。
2. 实现数据库连接封装、参数绑定、事务 RAII/等价回滚机制和统一错误转换。
3. 实现手机号登录/自动注册、站点/桩列表、未完成订单检查、开始充电、结束计费/结算。
4. 实现管理员登录、桩/站点/用户查询，以及远程重启和冻结/解冻所需服务接口。
5. 输出可供 A/C 直接运行的协议样例、种子账号和启动命令。

**完成标准**

- 本地最小客户端可完成一次成功充电订单并查询到状态变化。
- 管理端查询能看到同一桩和订单状态；统计查询有可追溯数据来源。
- 非法手机号、重复订单、无空闲桩、余额不足、权限失败、桩状态冲突、数据库失败均返回稳定错误码和可读消息。

### 阶段 2：联调与稳定性（9 月 7–10 日）

**目标**：支持阶段答辩的干净环境演示。

**任务**

1. 与 A/C 联调真实请求，冻结 v1 协议；变更必须同步文档和样例。
2. 补充并发/断连处理：半包/粘包、客户端超时、重复请求 ID、服务端优雅关闭。
3. 编写后端异常测试和一条端到端脚本；验证空数据库初始化和重复启动。
4. 参与 9 月 8 日编码规范检查，9 月 9 日 18:00 前完成 B 模块冻结候选版本。

**完成标准**

- 从新克隆目录按说明启动数据库、服务端和客户端，主链路可重复演示。
- 测试记录覆盖分工文件要求的六类异常；日志能定位请求 ID、错误原因和事务失败。
- 个人源码包只包含 B 负责部分及必要说明，小组包由 C 汇总。

### 阶段 3：反馈修复与扩展（9 月 11–16 日）

**优先级**

1. 先修复答辩阻塞缺陷和数据一致性问题。
2. 补充营收/利用率统计接口和大屏所需聚合口径。
3. 完善迁移、备份/重置演示数据和接口文档。
4. 基础功能稳定后，再评估向 `ml` 提供可追溯数据集；预测不是 B 的阶段 I 阻塞项。

**完成标准**：回归测试通过，接口版本和数据库版本可识别，第二阶段只提交本人增量代码/录屏。

## 4. 每日工作节奏与协作接口

- 每天开始前：从 `current.md` 和看板确认当天唯一优先任务；先同步会影响 A/C 的字段或协议变更。
- 每个提交：保持可构建，提交信息包含模块、动作和任务编号；附最小验证命令。
- 每次协议/Schema 变更：同时更新 `docs/architecture/*`、样例和受影响测试；通知 A/C。
- PRL 检查重点：状态转换是否合法、事务是否完整、错误是否可见、并发下是否会重复扣款/重复充电、是否泄露凭据。
- 联调约定：默认本地服务端端口和数据库路径写入 `config/example.env`；真实 Key 不进入仓库。

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 协议/字段反复变更阻塞客户端 | 阶段 0 冻结 v1；新增字段向后兼容，破坏性变化升版本 |
| 订单、余额、桩状态不一致 | 统一业务服务入口；事务覆盖关联写入；失败返回错误并记录请求 ID |
| Qt 多线程生命周期问题 | Socket 会话和数据库 worker 明确所有权；GUI 不直接触碰 worker 对象 |
| 答辩网络不可用 | 种子数据、地图 Mock、固定统计快照和离线启动开关 |
| 时间紧张导致 ML 挤占基础功能 | ML 仅在阶段 1 闭环和回归通过后排期 |
