# 用户端规范要求（A-S1-02 工作基线）

**模块**：`apps/user-client`
**技术**：Qt/C++，通过 `libs/protocol`/Socket 访问服务端
**依据**：仓库 `AGENTS.md`、`CONTRIBUTING.md`、`README.md`、`current.md` 和 `docs/requirements/requirements-matrix.md`。
**原则**：本文区分仓库指令、已冻结需求和待确认设计；字段/枚举/错误码不在本文重新定义。

## 0. 当前实现状态

- 当前基线是 Qt Widgets + `UserWindow`/`SessionManager` + `IUserService`/`MockUserService`；Mock 数据和离线路线用于并行开发，不代表后端 Socket 业务已完成。
- S1 真实腾讯地图驾车/步行基础导航仍是必做主链路。现有 README 标明真实 API 尚未打开，因此该项状态应写为“待联调/待验证”，不能写成已完成。
- 构建、QtTest 和 GUI 冒烟的真实结果以根目录 `current.md` 最新证据为准；无显示器或无依赖时必须明确记录阻塞。

## 1. 模块边界（必须遵守）

- 负责 Qt UI、页面切换、会话/本地交互状态、站点与桩展示、地图入口、预约/充电/计费/结算交互和用户资料/钱包界面。
- 通过单一网络/协议适配层访问 `server`；页面代码不得散落 Socket 连接、帧拼装或 JSON 序列化。
- 不直接打开或写入运行时 SQLite，不实现后端事务、余额扣款、并发占桩、权限判定或管理员功能。
- 不自行冻结 SQL 字段、订单/桩状态、Socket 帧、端口和错误码；未确认接口必须使用 Mock，并明确替换点。
- 长耗时网络、数据库、预测或地图操作不得阻塞 GUI 线程；后台线程不得直接更新 Widget，关闭时必须安全停止后台工作。

## 2. S1 必做功能

### A-S1-02-01 账号与会话

- 支持 11 位手机号免密登录；手机号格式错误在客户端提示且不发请求。
- 不存在的手机号由服务端自动注册；客户端展示默认昵称“用户+手机号后 4 位”、灰色头像和 0 元余额（具体字段以服务端契约为准）。
- 提供注册/登录成功、超时、断连、认证失败、写入失败和退出登录状态；退出时清理会话、选桩和订单临时状态。

### A-S1-02-02 地址、站点与桩查询

- 支持区域/地址输入，校验空值、长度和非法字符；合法输入可触发地理编码和站点查询。
- 地址转经纬度支持真实腾讯地图 API 与 Mock/离线路径；缺少 Key、网络失败或配额失败时降级并明确标识。
- 附近站点按需求口径展示并排序；站点卡片至少显示站名、价格、总桩数、空闲数和距离，缺失字段显示占位而非伪造。
- 站点详情显示桩编号、类型、功率和状态；状态文字与颜色统一，至少区分闲置、预约、充电、故障等服务端状态。

### A-S1-02-03 导航

- 站点详情提供驾车和步行入口；按需求矩阵通过 `QWebEngineView` 加载腾讯地图页面并展示基础路线，真实 Key 只从本地配置读取。
- 起终点坐标缺失时不发起无效请求；网络/Key/API 失败时提供可演示的 Mock/离线路线说明。
- 距离、预计时间和路线来源必须标注；不得把 Mock 结果写成实时导航。
- S2 只做重试、兼容性、错误提示和体验优化，不得成为 S1 基础导航的前置条件。

### A-S1-02-04 预约至结算

- 选桩前显示站点、桩、状态和必要的订单信息；提交中禁止重复点击。
- 依次承载未完成订单检查、预约、开始充电、计费、停止、结算和结果刷新；服务端状态是最终事实。
- 对重复订单、桩冲突、余额不足、状态不允许、超时、断连和数据库失败显示可理解提示；失败不得留下客户端假成功状态。
- 订单列表/详情至少能区分待预约、已预约、充电中、待结算、已完成、已取消和异常等最终服务端状态；金额和电量展示服务端返回值。

### A-S1-02-05 错误、加载与安全

- 所有异步入口有加载、成功、空数据、失败和重试状态；断连或失败不能用旧数据冒充新数据。
- 错误码映射为中文提示，同时保留请求编号/内部上下文以便排查；未知错误不能静默吞掉。
- UI、日志、截图和测试输出不得出现手机号以外的敏感信息、Socket 调试包或真实腾讯地图 Key。

## 3. 协议适配要求

1. `IUserService` 或等价适配层是页面与服务端之间的唯一业务边界；后端真实适配只替换该层及 DTO/枚举映射。
2. 适配层遵守 `libs/protocol` 的帧边界、信封、请求编号、响应关联、错误码、超时和心跳约定；协议未冻结前不得猜字段。
3. Mock 至少覆盖成功、空结果、认证失败、业务冲突、超时、断连和 malformed response，并保持与真实协议相同的调用边界。
4. 任意协议变更先检查生产者/消费者，更新协议文档、用户端适配、服务端实现和契约测试，再联调页面。

## 4. S2 承接范围

- 导航优化：失败重试、兼容性和体验改进，基础真实导航不可回退为唯一 Mock。
- 智能分析：只展示后端/模型服务提供的 1/6/24 小时负荷、空闲桩/高峰预测、低拥堵推荐和负荷预警；必须标注数据时间、版本、降级状态，不在客户端自行训练或伪造预测。
- 第二阶段接口和模型服务边界确定后，先更新需求矩阵、协议文档和 `current.md`，再增加页面。
