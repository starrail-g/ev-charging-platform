# 充电用户端详细要求与腾讯地图接入记录

更新时间：2026-09-09
适用平台：Linux 桌面环境（Ubuntu 22.04+）
客户端技术栈：Qt Widgets / C++

本文记录用户端第一阶段的详细功能要求、当前 Mock 实现边界和地图服务适配。2026-09-09 起以 PR #15 的 `docs/architecture/map-service-protocol.md` 为地图契约唯一事实来源：腾讯 Key、WebService 调用、缓存、审计、站点导入和桩快照由 B 服务端负责，用户端只发送 Socket Protocol v1 请求并渲染服务端结果。下文早期直连腾讯 API 的记录保留为历史过程，不代表当前生产路径。

## 一、产品定位

充电用户端运行在 Linux 桌面环境，使用 Qt 模拟手机端交互体验，为电动汽车车主提供从查找充电站、查看电桩、导航、预约、充电到结算的完整服务。

当前阶段允许使用确定性 Mock/离线数据并行开发，但它必须作为独立运行模式明确标识。选择 Socket 模式后，业务与地图请求只能访问服务端，不得自动切换到本地 Mock 服务，也不得在界面显示 Mock 专用字段、演示账号提示或 Mock 操作文案。

## 二、附近充电站查询

### 功能目标

用户登录后查看当前位置周边的充电站，快速找到可用充电资源。

### 交互要求

1. 支持下拉选择区域，软件层面模拟 GPS 定位。
2. 支持手动输入地址并提交定位。
3. 地址定位在 Socket 模式下通过服务端 `map.station.search` 的 `origin.kind=address` 完成；服务端负责腾讯地理编码，失败时客户端显示服务端错误或脱敏后的服务端备用数据，不在本地生成坐标。
4. 根据距离由近及远展示站点。
5. 支持站点列表刷新、关键词查询和基础空/错状态提示。

### 站点卡片字段

每个站点卡片需要显示：

- 站点名称；
- 充电价格，单位为元/度；
- 电桩总数与空闲数量；
- 距离，单位为公里；
- 站点地址；
- 营业或可用状态。

点击站点后进入该站详情，展示该站所有电桩。

### 电桩详情字段

每个电桩至少显示：

- 电桩编号；
- 电桩类型；
- 当前状态；
- 功率。

状态使用适配层统一映射，当前 Mock 状态包括闲置、已预约、充电中、故障、维护和暂不可用。

## 三、一键导航

### 功能目标

用户在站点列表或站点详情中选择目标站点，通过服务端 `map.route.plan` 获取从当前位置到目标充电站的路线规划。

### 交互要求

1. 起点为当前位置，也允许用户输入起点坐标或地址。
2. 终点为用户选择的目标充电站。
3. 支持驾车和步行两种出行方式。
4. 点击导航后展示路线结果、距离和预计时间（接口提供时）。
5. 地图页面使用 Qt WebEngine/QWebEngineView 承载本地离线/摘要视图，客户端不加载带 Key 的腾讯 JavaScript。
6. 查询失败、超时、空路线、无效坐标和无 Key 时必须给出可读提示。
7. 服务端不可用时显示明确错误，不由客户端生成路线；服务端返回缓存或 `server_mock` 来源时可渲染其结果，但界面统一标为“服务端备用数据”。本地 Mock/离线路线只属于显式 Mock 运行模式。

### 服务端负责的腾讯接口（客户端不直接调用）

| 场景 | 接口候选 | 说明 |
|---|---|---|
| 地址转坐标 | `GET https://apis.map.qq.com/ws/geocoder/v1/` | 地址 → 经纬度 |
| 关键词提示 | `GET https://apis.map.qq.com/ws/place/v1/suggestion` | 输入地址或站名时联想 |
| 周边站点/POI | `GET https://apis.map.qq.com/ws/place/v1/search` | `boundary=nearby(lat,lng,radius)`，关键词可使用“充电站” |
| POI 详情 | `GET https://apis.map.qq.com/ws/place/v1/detail` | 通过 POI ID 获取名称、地址、坐标等详情 |
| 驾车路线 | `GET https://apis.map.qq.com/ws/direction/v1/driving/` | 起点、终点和路线结果 |
| 步行路线 | `GET https://apis.map.qq.com/ws/direction/v1/walking/` | 起点、终点和步行路线结果 |

腾讯位置服务 WebService API 的 Key 只允许存在 B 服务端环境或被忽略的本地配置，不能进入用户端源码、响应、Git、日志、截图或本文。客户端只依赖 `map.station.search`、`map.route.plan` 两个服务端操作。

## 四、用户信息维护

### 登录机制

1. 输入 11 位手机号。
2. 手机号已存在：查询并验证后直接登录。
3. 手机号不存在：自动创建用户，默认昵称为“用户 + 手机号后 4 位”。
4. 默认头像为灰色头像，默认余额为 0 元。
5. 登录失败、超时、断连和参数错误需要显示用户可读提示。

### 信息展示

登录成功后展示：

- 用户头像；
- 用户昵称；
- 手机号；
- 钱包余额，单位为元；
- 当前连接和账号状态；Socket 模式不得出现 Mock 专用字段。

### 信息修改

- 支持从本地选择图片作为头像；
- 支持编辑和保存昵称；
- 输入充值金额后模拟支付成功；
- 充值成功后余额实时更新；
- 退出登录后清理会话和页面选中状态。

## 五、电动汽车充电主流程

### 主流程

```text
站点列表 → 站点详情 → 电桩列表 → 选择闲置电桩
→ 预约/创建订单 → 开始充电 → 停止充电
→ 待结算 → 结算完成 → 历史记录
```

### 进入充电页前检查

进入充电页面时查询当前用户是否有未完成订单：

- 有“充电中”订单：提示“您有未完成的充电订单，请先结算”，并进入结算状态；
- 无未完成订单：允许正常选择和预约电桩；
- 当前已有预约：充电页面展示“已预约”，允许开始充电或取消预约；
- 底部“充电”入口不主动弹窗；只有用户点击其他电桩时才提示已有预约或未完成订单。

### 电桩和订单状态

订单和电桩状态必须集中映射，不在页面中重复硬编码：

| 操作 | 订单状态 | 电桩状态 |
|---|---|---|
| 预约/创建订单 | 已预约 | 已预约 |
| 开始充电 | 充电中 | 充电中 |
| 停止充电 | 待结算 | 闲置 |
| 结算 | 已完成 | 闲置 |
| 取消预约 | 已取消 | 闲置 |

### 历史充电记录

历史记录按最近一次完成到更早记录排序，每条记录显示：

- 完成时间；
- 充电站地址；
- 花费金额。

不显示内部订单编号。页面同时显示历史次数和累计花费总结。

## 六、页面和体验要求

- 使用 21:38 手机端比例窗口和清晰的底部导航；初始尺寸为 420 x 760，可在 315 x 570 至 840 x 1520 范围内等比例缩放；
- 未登录用户不得进入需要身份的订单操作；
- 所有异步操作均有加载、成功、失败、空数据和超时状态；
- 请求期间禁用重复提交；
- 错误信息不能泄露 Key、数据库路径、内部堆栈或敏感字段；
- 配色与管理端日间主题一致：浅灰背景、近白表面、深色正文、蓝色主要操作和绿色选中/闲置状态；输入框、按钮、卡片和状态面板使用 6-8 px 圆角；
- 页面切换和返回不能造成空白页或状态残留。

## 七、服务适配层边界

页面只依赖统一的 `IUserService`/DTO，不直接调用临时函数，也不直接访问 SQLite。接口范围至少包括：

- 登录、注册/自动创建、用户信息和资料修改；
- 站点查询、电桩查询；
- 地址解析、路线查询；
- 当前订单、历史订单；
- 创建/预约订单、取消预约、开始充电、停止充电、结算。

`MockUserService` 是独立的确定性演示实现；`SocketUserService` 已按 Protocol v1 隔离字段、状态、错误码和时间格式映射。Socket 模式不得访问 `MockUserService` 或 `MockMapService`，服务端失败必须保持可观察。

## 八、腾讯地图首次接入验证方案

### 1. 本地配置

使用本地环境变量注入，不在命令行回显 Key：

```bash
read -s TENCENT_MAP_KEY
export TENCENT_MAP_KEY
export TENCENT_MAP_ENABLED=1
```

仓库只保留 `config/example.env` 占位符。

### 2. 首次 API 探测

使用深圳南山区固定坐标进行可复现探测。按腾讯当前文档，周边搜索半径取值为 10–1000 米，距离排序参数为 `_distance`；统一执行脱敏脚本：

```bash
bash scripts/tencent_poi_probe.sh
```

检查重点：HTTP 是否成功、JSON `status` 是否为 0、`data` 是否包含 `id`、`title`、`address`、`location.lat`、`location.lng`。腾讯 POI 返回的价格、总桩数和空闲数通常不是通用地图字段，不能直接假设可从地图 API 获取；这些业务字段仍应来自 B 服务端或本地 Mock 适配。

### 3. 结果记录规则

- 不记录完整请求 URL，因为 URL 中包含 Key；
- 只记录时间、接口名称、HTTP 状态、腾讯返回 `status`、结果数量和字段完整性；
- 错误只记录脱敏后的错误码/消息；
- 成功返回的 POI 只转换为 `MapPoi`，不得直接转换或冒充业务 `Station`；预约、价格、桩数量和状态仍以 `IUserService` 数据为准。

### 4. 首次虚拟机探测结果（2026-09-02）

- 虚拟机检查结果：`TENCENT_MAP_KEY` 未注入，未读取或打印任何真实 Key。
- 使用占位 Key 调用周边搜索接口时，接口返回 HTTP 200、腾讯 `status=311`、消息为“key格式错误”。
- 结论：虚拟机到腾讯接口的网络路径可达，接口地址和请求参数形态已得到初步验证；真实 POI 数据尚未验证，需在虚拟机本地安全注入有效 Key 后运行 `scripts/tencent_poi_probe.sh`。
- 该探测只验证地图 POI 可达性，不会把 POI 的价格、桩总数、空闲数或实时状态误认为业务数据。

### 5. 真实服务与页面验收结果（2026-09-07）

- 通过 VM 临时环境变量注入测试凭据，地址解析、附近 POI、驾车路线和步行路线均返回 HTTP 200、腾讯 `status=0`，必要字段完整；附近搜索返回 20 条位置结果。
- 在 VM 图形会话 `DISPLAY=:0` 中，真实 `QWebEngineView` 成功加载腾讯 GL JS、一个测试标记和一条固定折线；真实地图套件 11 passed、0 failed。
- `offscreen` 模式没有可用 WebGL 上下文，因此只用于离线降级烟测，不作为真实 GL 地图验收环境。
- 测试结束后已清除环境变量；仓库、日志和文档均不保存测试凭据。该凭据曾在仓库外明文披露，正式演示前必须轮换并复跑脱敏检查。
- 后续人工界面复核发现该测试 Key 达到当日调用上限，腾讯返回 `status=121`。服务端应将其映射为配额/限流错误；Socket 客户端显示服务端错误或服务端缓存/备用结果，不在本地伪造腾讯结果。
- 初始 420×760、可按 21:38 比例缩放的窗口中的地图页已改为可滚动内容、紧凑路线控制和单一服务端结果/离线示意图，避免 WebEngine、POI、业务站点及状态文本互相挤压或重复展示。

## 十一、A-S2-01 实现边界

- 地图模块文件位于 `apps/user-client/src/map_service.*`、`server_map_service.*` 和 `map_web_view.*`；页面只调用统一异步接口。`tencent_map_service.*` 仅保留为早期实现的隔离测试材料，不属于生产路径。
- 起点支持地址或 `纬度,经度`；目标必须来自有有效坐标的业务站点。地图 POI 无法关联业务站点时只可查看位置摘要，不能预约或充电。
- 每次定位、POI 或路线请求都有 generation；新请求、切换页面和退出登录会取消旧网络请求，旧响应不会覆盖当前地图状态。
- 路线由服务端返回米、秒和最多 4096 个折线点；客户端校验坐标和字段完整性，没有有效折线时只显示摘要。
- 用户端不读取 `TENCENT_MAP_KEY`；Key 和腾讯上游日志仅存在 B 服务端。客户端只需配置 `EV_USER_CLIENT_TRANSPORT`、`EV_SERVER_HOST` 和 `EV_SERVER_PORT`。
- 老师材料将基础真实导航归于 S1、A-S2-01 归于导航优化；当前交付按 PR #15 将 A-S2-01 客户端部分定义为服务端协议适配与降级兼容，腾讯 API 实现归 B。
