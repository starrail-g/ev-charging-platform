# 缺陷日志（Defect Log）

> 编号规则：`C-S1-<三位序号>`（第一阶段），第二阶段使用 `C-S2-<三位序号>`。
> 状态：`待修复` / `修复中` / `已修复` / `已关闭（非缺陷）` / `延后`。
> 更新时机：每日结束固定动作 + 每次评审/测试发现缺陷时。

## 字段说明

| 字段 | 含义 |
|---|---|
| 编号 | C-S1-001 起，顺序递增，不复用 |
| 严重级别 | P0（阻塞构建/演示/核心功能）、P1（功能缺陷，有绕行）、P2（体验/文档小问题） |
| 模块 | 管理端 / 大屏 / 测试 / 文档 / 发布 |
| 描述 | 一句话缺陷 |
| 复现步骤 | 可复现的最小步骤 |
| 负责人 | 修复责任人 |
| 目标日期 | 计划修复日期 |
| 状态 | 见上 |

## 缺陷列表

| 编号 | 严重级别 | 模块 | 描述 | 复现步骤 | 负责人 | 目标日期 | 状态 |
|---|---|---|---|---|---|---|---|
| （空） | | | | | | | |

## 关闭规则

- P0 必须当日修复并全量复测后才可标记 `已修复`。
- P1 仅在接口不变的前提下修复；P2 延后到第二阶段。
- `已关闭（非缺陷）` 必须写一行关闭原因。
