> 版本：v1.1，2026-09-14
> 适用周期：2026-09-12 至 2026-09-17；个人报告：2026-09-18
> 依据：`current.md`、`docs/requirements/requirements-matrix.md`、课程说明会材料、`04.数据集最终版/`

## 1. 阶段目标

在不破坏第一阶段登录、站点查询、预约、充电、结算和管理端基本查询的前提下，完成一条可解释、可重复、可降级的大数据链路：

```text
原始 CSV -> ODS 原始层 -> DWD 清洗明细 -> DWS 聚合特征
          -> ADS 指标/预测结果 -> Flask API -> ECharts 大屏/Qt 页面
```

本阶段的最低可交付结果：

1. 以第一阶段 SQLite Schema v0.4 为业务事实模型，由确定性生成器构造可复用的用户、站点、桩、订单和钱包数据；在入库前事件层注入至少 3 类可复现质量问题，再由 PySpark 识别和清洗，最终合法数据可重跑、可对账。
2. 用 SparkSQL 产出营收、订单量、能耗、站点利用率和设备状态等 ADS 指标，能与第一阶段演示数据区分并标注来源。
3. 产出未来 1 小时、6 小时、24 小时的充电负荷和空闲桩预测，给出高峰时段、低拥堵站点推荐和负荷预警。
4. 提供模型服务边界：输入、输出、模型版本、训练时间、数据时间范围、失败原因均可追溯；服务失败只降级为基础统计，不阻断核心充电业务。
5. 将结果接入可交互 Web 大屏，并在管理端提供分析摘要入口；大屏覆盖用户、设备、订单、能源、收益、站点和服务质量七类分析视角，录屏、源码包、测试用例和报告材料可按课程要求提交。

不在本阶段新增真实支付、硬件控制、私有 mTLS、复杂调度优化或替换第一阶段 Qt/Socket/SQLite 架构。二阶段工作台与一阶段客户端保持独立，采用现有原生 ES modules + 本地 ECharts 实现侧边导航切页；页面按分析域聚合并通过 hash 可直达，避免重写已验收的大屏。若课程验收明确要求 Vue 路由页，再在同一 API 契约上新增独立 Vue 页面，不改变数据和服务边界。

## 2. 一阶段基线与输入数据判断

一阶段已经具备 Schema v0.4、Socket Protocol v1、Qt 用户端/管理端、离线 ECharts 大屏、腾讯地图边界和确定性桩模拟器。二阶段已完成首个可复现的数据/模型/API/UI 闭环：`ml/` 提供 Schema v0.4 生成器、质量隔离、Spark 分层、MLlib 训练推理和 Flask 只读服务，Dashboard 与管理端概览均已接入；当前大屏进一步增加可交互分析工作台，按模块切换用户、设备、订单、能源、收益、站点和服务质量视角，并单独展示 1/6/24 小时机器学习预测。

二阶段主数据源不是外部 CSV，而是“Schema v0.4 + seed + 确定性生成规则”生成的合成业务数据库。生成的数据库必须通过现有 Schema 约束、触发器、外键和 `revenue_daily` 视图校验，再导出 ODS/DWD/DWS/ADS。新增 CSV 仅作为字段范围、异常场景和遥测特征的参考，不得直接冒充项目订单或站点事实：

| 文件 | 规模 | 业务含义 | 可直接使用的字段 | 必须处理的问题 |
|---|---:|---|---|---|
| `nvv2t.csv` | 3395 行、22 列 | 充电会话/订单事实 | 电量、费用、时段、星期、用户、站点、充电时长 | 年份为 `0014/0015` 的匿名日期；55 条零电量、3016 条零费用；1 条时长超过 24 小时；费用大量为 0，不能直接当作完整营收 |
| `nvv2t_md_end.csv` | 105 行、8 列 | 站点维表 | 站点、地址、设备数、类型、开放时间 | 105 个站点 ID 对应 25 个重复地址；设备数 1–40；地址/站点名称需去空白并保留原值 |
| `dsv13r2.csv` | 1594 行、11 列 | 电池遥测样本 | SOC、电压、电流、温度、可用能量/容量 | `record_time` 全部为 `2.02E+13`，无法作为真实时间轴；`esd` 唯一但没有站点/会话外键，只能作为电池健康特征样本，不能伪造真实站点负荷关联 |

日期不明确时不得猜测真实年份。清洗层采用“相对时间归一化”：保留 `source_created`，按原始日期排序映射到配置的 `analysis_base_date`，同时写入 `date_normalization_method=relative_offset`。报告中明确这是脱敏样本的分析时间，不是生产订单发生日期。

### 待确认的数据生成口径

以下参数在编码前由负责人确认，未确认前不得写入生成器默认值：

- 分析时间窗和时区（建议 UTC、至少 90 天，以支持 1/6/24 小时预测）。
- 生成规模（用户、站点、每站桩数、历史订单数）及是否将现有 `dev.sql` seed 作为基线一并载入。
- 营收分布：订单 `total_amount_cents` 是否完全按 Schema 结算公式生成，还是需要保留一定比例零费用/异常费用作为质量场景。
- 天气、节假日和电池遥测是否作为分析层独立事实生成；它们不属于当前核心 Schema，不能伪造外键后写入订单表。
- 质量问题注入清单及比例。注入记录只存在于原始事件层，清洗后的 SQLite 和业务库必须 100% 符合 Schema。

## 5. 交付物与验收门

### 必交文件

- `docs/release/stage2-plan-2026-09.md`、`docs/release/stage2-implementation-guide.md`。
- `ml/` 数据字典、质量报告、分层脚本、特征/模型说明、API 契约和测试记录。
- 大屏增量页面或组件；现有 Dashboard 离线入口必须保留。
- 第二阶段测试用例、录屏、PPT 增量页、源码包和个人报告素材。

### Gate S2-DATA

- 同一输入运行两次，DWD/DWS/ADS 的行数、校验和和关键汇总一致。
- 质量规则至少覆盖：空值/类型、重复主键、日期解析、负值/零值、范围、维表关联、异常时长。
- 原始层只读；坏记录进入 `quarantine` 并附 `quality_code`，不能静默丢弃。

### Gate S2-ML

- 三个预测窗口均有数值、单位、预测生成时间、数据截止时间和 `model_version`。
- 记录基线指标（MAE 或 RMSE）；数据不足时返回 `insufficient_data`，不伪造精度。
- 推荐结果至少包含站点 ID、预测空闲率、预测负荷、排序理由和结果时间。
- 预警包含等级、阈值、实际/预测值、窗口和建议动作；同一快照不重复告警。

### Gate S2-INTEGRATION

- Flask API 可本地启动；大屏正常/空/错误/离线状态均可操作。
- 模型服务停止时，站点查询、预约、充电、结算、管理员登录仍通过原路径工作。
- 运行验证记录命令、环境和结果。Qt 相关构建仍只使用 `qmake6`，不得以 CMake 作为证据。

## 6. 风险与取舍

| 风险 | 处理决定 |
|---|---|
| 样本日期脱敏且遥测无时间/站点外键 | 使用相对日期；遥测只做健康特征或独立分析，不制造跨表事实 |
| 费用大量为 0 | 同时展示“原始费用”和“估算营收（若启用）”，默认不把估算值冒充真实结算收入 |
| Hadoop/Spark 环境安装耗时 | 先用本地 Spark 单机模式完成验收；Hadoop 只作为课程环境记录，不让集群安装阻塞交付 |
| S2 时间短 | 先完成可解释的统计/基线模型，再增加 MLlib 模型；不追求未经验证的复杂深度学习 |
| 模型或 Flask 不可用 | 使用最近观测/规则基线降级，并显示来源和状态；不阻塞 S1 业务 |
| 引入 Vue 造成大屏重写 | 保留现有离线 ECharts 壳；只有分析页单独需要复杂状态时才增加 Vue，避免重复实现 |
