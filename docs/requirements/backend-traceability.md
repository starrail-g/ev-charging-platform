## 状态机验收重点

下列规则来自需求中明确的业务约束，最终状态名称以协议 v1 和数据库 v0.2 为准：

1. 同一用户同一时间最多一笔未完成充电订单。
2. 仅可使用空闲充电桩开始订单；开始成功后必须更新为占用状态。
3. 结算前按订单记录计算费用；余额不足时订单和桩不得错误进入已完成/闲置状态。
4. 成功结算须原子更新订单、钱包余额/流水和充电桩状态。
5. 故障桩不可被用户发起充电；管理员操作的合法状态由协议和数据库约束共同保证。

## 后端异常用例基线

| 用例 ID | 场景 | 预期 |
|---|---|---|
| BE-T01 | 少于或多于 11 位的手机号登录 | 参数错误；不写入用户 |
| BE-T02 | 已有未完成订单时再次开始充电 | 业务冲突；桩和订单不变 |
| BE-T03 | 对非空闲桩开始充电 | 桩状态冲突；不创建订单 |
| BE-T04 | 结算金额大于钱包余额 | 余额不足；订单、钱包、桩保持结算前一致 |
| BE-T05 | 数据库写入失败 | 事务回滚；返回内部/数据库错误且记录请求 ID |
| BE-T06 | 连接中断或非法长度帧 | 只关闭该会话；服务端继续服务其他请求 |

需求矩阵未定义的字段、费率公式、认证令牌、超时值和最终状态枚举，均由协议/数据库 v1 设计文档显式决定，不能由客户端自行假定。
