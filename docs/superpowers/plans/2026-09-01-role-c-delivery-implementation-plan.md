# 角色 C 交付实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 2026 年 9 月 10 日前交付可构建、可演示、可测试的 Qt 管理端、ECharts 数据大屏及第一阶段过程/发布材料，并在 9 月 17 日前完成评审修复和第二阶段交付。

**Architecture:** 管理端采用页面层、数据仓库接口和 Mock/Socket 双实现分离；大屏通过本地 HTTP 静态服务加载仓库内 ECharts 与固定 JSON，并保留无需 `fetch` 的内嵌数据备用入口。角色 C 不实现服务端核心，通过 9 月 7 日 18:00 接口闸门决定真实联调或经 A 批准的 Mock 降级。

**Tech Stack:** Ubuntu 22.04+、Qt 6 / C++、Qt Widgets、Qt Network、Qt Test、HTML/CSS/JavaScript、ECharts、本地 Python HTTP 服务、Git/GitHub Pull Request。

## 6. 第一阶段验证命令

选定 CMake 时：

```bash
cmake -S apps/admin-client -B build/admin-client
cmake --build build/admin-client -j
ctest --test-dir build/admin-client --output-on-failure
```

选定 qmake 时：

```bash
mkdir -p build/admin-client
cd build/admin-client
qmake ../../apps/admin-client/admin-client.pro
make -j
make check
```

大屏标准入口：

```bash
python3 -m http.server 8000 --directory dashboard
curl -I http://127.0.0.1:8000/
curl -I http://127.0.0.1:8000/data/demo-dashboard.json
```

预期：两个 `curl` 请求均返回 `200 OK`；浏览器控制台无资源加载错误，三张核心图表均有数据。

敏感信息检查：

```bash
git status --short
git grep -n -E '(api[_-]?key|token|secret|password)[[:space:]]*[:=][[:space:]]*[^$<{]'
git ls-files '*.db' '*.sqlite' '*.sqlite3' '.env' '.env.*'
```

预期：只显示允许的配置示例，不出现真实 Key、Token、运行数据库或本地 `.env`。

## 10. 进度判定规则

每天只使用以下四种状态：

- `未开始`：没有可验证产出。
- `进行中`：有分支或文档变化，但未满足退出条件。
- `已完成`：有构建/测试/截图/提交之一作为验收证据。
- `阻塞`：明确记录阻塞人、缺失输入、首次发现时间和升级时间。

进度百分比按完成工作包工时计算，不按“页面看起来差不多”估算。只有通过当日退出条件的工时才计入完成量。
