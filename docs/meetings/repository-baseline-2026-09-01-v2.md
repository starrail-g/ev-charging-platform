## 3. AGENTS.md 的产品与架构基线

- 用户端必须覆盖：站点发现、导航、账号、预约、充电、计费、结算，以及模拟位置/地址选择、腾讯地图、资料和钱包界面。
- 管理端覆盖管理员登录、统计、桩管理、站点管理、用户管理；大屏使用 ECharts；`ml/` 覆盖充电负荷预测、站点推荐和负荷预警。
- 五类最低持久化实体是用户、充电站、充电桩、充电订单和管理员；具体字段/枚举未冻结时不得臆造。
- 数据流固定为：Qt 客户端 → Socket/统一协议 → `server` → 数据库访问层 → SQLite。用户端不得直连运行时 SQLite，Widget 中不得放 SQL/事务。
- `libs/protocol` 是唯一通信契约归属。修改协议时必须检查生产者/消费者、更新文档和代码，并验证通信路径。
- 充电、计费、结算、钱包、桩状态、订单状态是一致性敏感流程：显式状态迁移、重复/非法操作校验、数据库失败处理、可观察错误和避免半更新均为必需。
- GUI 线程不得阻塞长耗时网络、数据库、预测等工作；跨线程使用 Qt 信号/槽等既有机制，后台线程不得直接更新 Widget，关闭时不得访问已销毁对象。
- 腾讯地图是外部服务边界，必须支持受控配置或 Mock/模拟行为；项目凭据不得硬编码。
- 项目未把 CMake 或 qmake 预先指定为权威构建系统；验证必须走仓库实际存在的构建/测试路径，不存在时如实报告限制。

## 4. CONTRIBUTING.md 的交付基线

- 不直接在 `main` 开发或 push；每个任务使用独立分支，完成后通过 Pull Request 合并，合并前至少一次代码检查。
- 分支类型使用 `feature/`、`fix/`、`docs/`、`test/`、`refactor/` 或 `chore/`；一个分支尽量只解决一个明确问题。
- 提交前检查 `git status`，只添加本任务文件；AI 生成代码由提交者负责理解并测试。
- 不提交密码、API Key、Token、私钥；不使用 `git push --force`；AI/Codex 不得擅自 push 或合并。
- 公共接口、Socket 协议、数据库结构和架构的重要变化必须同步正式文档。
